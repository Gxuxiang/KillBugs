# 已定的设计决策

> 2026-10-04 讨论确定。这些是**约束**，实现时不要再重新发明一遍。

## 撤离

- 只有**全员存活且都在撤离区域内**才开始计时。倒地的队友必须先被救起来 ——
  这条让救援从"锦上添花"变成撤离的必经环节。
- 有人离开区域时计时**暂停**，不重置。（4 个人很难保持完美同步，重置会变成互相甩锅。）
- 计时期间刷一波大规模虫潮。
- 撤离点每过几波随机出现一次；出现前 UI 有预告（"X 波后出现"），出现后屏幕边缘有方向指示。
- **有人撤离成功 = 这一局结束**，全队一起结算。

## 搜

- 虫子随机掉落（药包、材料）。
- 迷宫的房间里能找到珍贵材料。
- 材料是主要搜的东西，两个去处：局外合成枪械/装备、卖给商店换金币。

## 风险

- 团灭 = **装备和所有携带物品全部掉光，包括从仓库带进去的装备**（塔科夫式，赌注拉满）。
- **只有击杀赚的金币不掉。** 金币因此必须跨局持久化，且只用于局外商店。
- 存档里至少要有：**仓库（材料/装备）+ 金币**。

## 救援

- 倒地出现救助圈，队友进圈开始读条。
- 读完 → 复活，回复**一半**血量。
- 队友**离开圈再进 = 重新计时**（注意这条和撤离的"暂停"不同，是有意的）。

## 局外

- 仓库 + 配装：进局前选好装备带进去。
- 商店：卖材料换金币，金币买物品。
- 合成：材料 → 更强的枪械/装备。

## 阶段 4 的前置警告（重要）

虫群是**自定义转向 + 空间哈希分离**，完全不走 NavMesh —— 这恰恰是它 600 只能跑得动的原因。
地图一旦从平板变成有墙的房间，**虫子会直接撞墙、卡在墙角和门框上**。
给 600 只虫子做 NavMesh 寻路基本等于放弃现在的性能预算。

可行解是**流场（flow field）**：在网格上算"到玩家"的方向场，虫子查表转向，
开门关门时局部重算即可。这和现有的空间哈希是同一路子。
**这是一整块独立工程，不要和地图生成捆在一起做。**
